# Формат данных Art Content Planner

Приложение хранит пользовательские данные локально и переносит их между устройствами одним JSON-файлом. Сервер или платная облачная база для импорта и экспорта не требуются.

## Версия схемы

Поле `version` обязательно для новых экспортов и содержит семантическую версию схемы. Текущая версия — `2.0.0`.

- файлы без `version` считаются устаревшей схемой `1.0.0`;
- старые поддерживаемые схемы последовательно обновляются перед валидацией;
- файл с более новой основной версией отклоняется, чтобы приложение не удалило неизвестные ему данные;
- миграция никогда не должна изменять исходный объект или удалять пользовательские поля до валидации.

## Структура верхнего уровня

```json
{
  "version": "2.0.0",
  "settings": {},
  "monthlyPlans": [],
  "posts": [],
  "ideas": [],
  "paintings": [],
  "services": [],
  "offers": [],
  "campaigns": [],
  "hookLibrary": [],
  "storySequences": [],
  "rubrics": [],
  "contentBalance": {},
  "seoCluster": [],
  "lastUpdated": "2026-08-03T12:00:00.000Z"
}
```

Даты и время сохраняются строками: календарная дата — `YYYY-MM-DD`, время — `HH:mm`, временная отметка — ISO 8601 в UTC.

## Изображения идей

Поле `ideas[].images` — массив строк с изображениями в формате Data URL. Оно входит в общий JSON и поэтому переносится вместе с остальными данными без отдельного файлового сервиса.

```json
{
  "id": "idea-id",
  "createdAt": "2026-08-03T12:00:00.000Z",
  "title": "Эскиз новой серии",
  "description": "",
  "tags": [],
  "images": ["data:image/webp;base64,..."]
}
```

Для совместимости миграция из версии 1 добавляет пустой массив `images`, если поле отсутствует.

## Правила развития схемы

1. Новое необязательное поле должно иметь безопасное значение по умолчанию.
2. Ломающее изменение повышает основную версию и получает отдельную миграцию в `src/data/migrations`.
3. Экспорт и импорт должны использовать один и тот же валидатор.
4. После цикла `экспорт → импорт → экспорт` ни одно поддерживаемое поле не должно теряться.
5. Вложения остаются частью JSON, даже если рабочее браузерное хранилище в будущем будет переведено на IndexedDB.
