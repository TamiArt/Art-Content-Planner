# Art Content Planner

Личный контент-оператор для художника: генерация контент-плана, календарь публикаций, банк идей, каталог работ, услуги, офферы и аналитика.

## Основные возможности

- Генератор контент-плана на месяц с выбором дней, времени, платформ и целей.
- Календарь в режимах месяц, неделя, список и канбан.
- Редактор постов, промпт-билдер, SEO/LSI-ключи и хэштеги.
- Банк идей, каталог картин, услуги и офферы.
- Ручная аналитика публикаций.
- Экспорт и импорт JSON для резервного копирования.
- Аккаунт и синхронизация данных между устройствами.
- Локальная копия данных в браузере для устойчивой работы интерфейса.

## Архитектура

Интерфейс — React 18 + TypeScript + Vite. Production frontend размещается на Vercel.

API аккаунта и синхронизации — Cloudflare Worker (`worker/index.ts`). Данные аккаунтов, сессий и синхронизируемый snapshot хранятся в Cloudflare D1. Vercel проксирует `/api/*` в Worker, поэтому клиент использует same-origin `/api` и HttpOnly cookie.

Локальная разработка `npm run dev` также проксирует `/api` в production Worker. При необходимости адрес можно заменить через `VITE_API_PROXY_TARGET`.

> В репозитории один актуальный backend: Cloudflare Worker + D1. Старый Node/SQLite сервер удалён, чтобы локальная и production-архитектуры не расходились.

## Безопасность аккаунта

- Пароль: PBKDF2-SHA-256 с индивидуальной солью и server-side `AUTH_SECRET`.
- Сессия: случайный токен; в D1 хранится только HMAC-хэш токена.
- Cookie: `HttpOnly`, `SameSite=Strict`, `Secure` в production.
- API проверяет `Origin` для изменяющих запросов и использует optimistic revision для синхронизации.

`AUTH_SECRET` должен быть задан как Cloudflare secret и не храниться в репозитории.

## Синхронизация

Клиент хранит локальную копию и серверную revision. При конфликте revision локальное ожидающее изменение объединяется с более свежим серверным snapshot и повторно отправляется, чтобы обычное редактирование или добавление на одном устройстве не терялось из-за параллельной работы другого устройства.

Текущее ограничение: snapshot-модель не содержит tombstones, поэтому одновременные удаления на нескольких устройствах нельзя разрешить безошибочно. Для этого потребуется отдельный журнал изменений или метаданные удалений.

## Быстрый старт

Требуется Node.js 22.

```bash
npm ci
npm run dev
```

Откройте адрес Vite (обычно `http://localhost:5173`). `/api` будет проксироваться в Cloudflare Worker.

Проверки перед изменениями:

```bash
npm test
npm run build
```

`npm test` проверяет миграции/валидацию данных, импорт/merge и регрессионный сценарий разрешения sync-конфликта.

## Production

Frontend собирается командой `npm run build`; Vercel использует `vercel.json` и направляет `/api/:path*` в Cloudflare Worker.

Worker находится в каталоге `worker/`:

- `worker/index.ts` — исходный код API;
- `worker/wrangler.toml` — конфигурация Worker и D1 binding;
- `worker/migrations/` — схема D1.

Перед ручным обновлением Worker проверьте, что `AUTH_SECRET` настроен в Cloudflare, а `APP_ORIGIN` соответствует production frontend.

## Данные и резервные копии

Серверная копия хранится в D1, локальная — в браузере. Экспорт JSON через настройки остаётся дополнительной пользовательской резервной копией и способом переноса данных.

## PWA

Манифест и иконки подготовлены для добавления приложения на главный экран. Полноценное service-worker offline-кеширование пока не реализовано.

## Структура проекта

```text

scripts/             проверки данных и синхронизации
worker/              Cloudflare Worker + D1 migrations
public/              PWA-манифест и статические ресурсы
.github/workflows/   CI quality checks
```
